Una web está lista para publicarse cuando las tareas principales funcionan, el contenido está aprobado, la medición se ha probado y existe una forma de recuperar el servicio. No hace falta aplazar el lanzamiento por un detalle decorativo, pero sí por un formulario roto, un precio incorrecto o una política sin revisar.

Usa esta checklist en un entorno de prueba y repítela sobre el dominio final. Algunas funciones cambian al activar HTTPS, redirecciones, cookies, correo o pagos reales.

## 1. Contenido e identidad

- [ ] Cada página tiene un objetivo y una acción principal.
- [ ] Nombres de servicios y productos coinciden con la oferta actual.
- [ ] Precios, impuestos, horarios, zonas y plazos han sido aprobados.
- [ ] Dirección, teléfono y correo son iguales en toda la web.
- [ ] No quedan textos de demostración, marcadores o botones sin destino.
- [ ] Las afirmaciones se pueden demostrar y no prometen resultados garantizados.
- [ ] Los proyectos, logotipos y testimonios tienen permiso y son auténticos.
- [ ] Las imágenes corresponden al negocio o tienen licencia adecuada.
- [ ] No se publican datos personales dentro de documentos o nombres de archivo.
- [ ] Al menos otra persona ha revisado ortografía, cifras y enlaces.

Abre cada página con la pregunta del cliente en mente. Si el texto necesita una explicación verbal del equipo para entenderse, todavía falta información.

## 2. Navegación y enlaces

- [ ] El logotipo lleva al inicio.
- [ ] El menú funciona con ratón, teclado y pantalla táctil.
- [ ] La página actual se reconoce cuando aporta orientación.
- [ ] No hay enlaces rotos ni destinos de prueba.
- [ ] Los enlaces externos importantes abren la URL correcta.
- [ ] Teléfono, correo, WhatsApp y mapa funcionan en móvil.
- [ ] Los botones usan nombres que explican la acción.
- [ ] Se puede llegar a todas las páginas importantes mediante enlaces normales.
- [ ] La página 404 ayuda a volver a una sección útil.

Prueba también volver atrás después de usar un filtro, abrir un menú o empezar un formulario. La persona no debería perder el trabajo sin aviso.

## 3. Formularios, reservas y contacto

Envía cada formulario con datos válidos, campos vacíos y formatos incorrectos.

- [ ] Las etiquetas permanecen visibles al escribir.
- [ ] Los campos obligatorios se indican antes de enviar.
- [ ] Los errores aparecen junto al campo y explican la corrección.
- [ ] La información válida se conserva tras un error.
- [ ] El botón evita envíos duplicados o los gestiona.
- [ ] La confirmación aparece en pantalla y, si corresponde, por correo.
- [ ] El mensaje llega al buzón correcto y no termina siempre en spam.
- [ ] El equipo sabe quién responde.
- [ ] Se explica un plazo de respuesta solo si puede cumplirse.
- [ ] Los datos solicitados son necesarios para la finalidad indicada.

En reservas, prueba disponibilidad, zona horaria, confirmación, modificación, cancelación y falta de plazas. En tienda, prueba pago aprobado, rechazado y reembolso antes de aceptar pedidos reales.

## 4. Móvil y distintos navegadores

- [ ] Inicio, servicios, contacto y compra se usan en pantalla estrecha.
- [ ] No existe desplazamiento horizontal accidental.
- [ ] Texto y botones no quedan detrás de avisos flotantes.
- [ ] Los controles tienen tamaño y separación suficientes.
- [ ] El teclado del móvil no tapa campos ni acciones.
- [ ] Imágenes y vídeos respetan el ancho disponible.
- [ ] El menú se abre, recorre y cierra correctamente.
- [ ] La web funciona en los navegadores principales del público.
- [ ] Se ha probado una conexión móvil, no solo wifi rápido.

No limites la revisión a un emulador. Un teléfono real descubre problemas con teclado, barras del navegador, gestos y rendimiento.

## 5. Accesibilidad básica

- [ ] Se puede recorrer toda la web con teclado.
- [ ] El foco es visible y sigue un orden lógico.
- [ ] Existe un H1 generado por la plantilla y los H2/H3 mantienen jerarquía.
- [ ] Texto y controles tienen contraste suficiente.
- [ ] La información no depende solo del color.
- [ ] Las imágenes informativas tienen alternativa útil.
- [ ] Las imágenes decorativas no añaden ruido al lector de pantalla.
- [ ] El zoom al 200 % no oculta contenido ni acciones.
- [ ] El movimiento se puede reducir o detener cuando corresponde.
- [ ] Los mensajes de estado y error son perceptibles.

Una comprobación automática de accesibilidad ayuda, pero no sustituye la prueba manual ni una auditoría cuando sea necesaria. Recorre al menos las tareas principales con teclado y comprueba que el foco sea visible.

## 6. SEO e indexación

- [ ] Cada página indexable tiene título y descripción propios.
- [ ] Existe una URL canónica coherente.
- [ ] Las páginas de prueba no pueden indexarse.
- [ ] La web pública no conserva un `noindex` o bloqueo temporal.
- [ ] `robots.txt` no bloquea recursos o secciones necesarias.
- [ ] El sitemap incluye URLs canónicas e indexables.
- [ ] Redirecciones desde URLs antiguas llevan al destino equivalente.
- [ ] No hay cadenas largas ni bucles de redirección.
- [ ] Encabezados y contenido responden a una intención clara.
- [ ] Las páginas no repiten texto cambiando solo una localidad o palabra.
- [ ] Los datos estructurados coinciden con el contenido visible y se validan.
- [ ] Imágenes tienen nombres, dimensiones y alternativas apropiadas.

Google recomienda enviar el sitemap mediante Search Console o declararlo en `robots.txt`, aunque un sitemap es una pista y no garantiza indexación. Inspecciona las URLs prioritarias después del lanzamiento.

## 7. Analítica y medición

- [ ] Analytics registra páginas en el dominio final cuando corresponde.
- [ ] Search Console está verificada para la propiedad adecuada.
- [ ] Los eventos representan resultados reales, no clics ambiguos.
- [ ] Formularios, llamadas, reservas y compras se prueban una sola vez.
- [ ] Las visitas internas se identifican si el plan de medición lo requiere.
- [ ] Los parámetros de campaña se conservan según la configuración.
- [ ] El consentimiento se integra con las etiquetas de acuerdo con la revisión aplicable.
- [ ] El acceso pertenece al negocio y hay más de un administrador cuando conviene.
- [ ] Se ha documentado qué mide cada evento.

Google Analytics y Search Console miden partes distintas. No retrases un lanzamiento solo para registrar cada interacción posible; sí comprueba las acciones que determinan si la web cumple su objetivo.

## 8. Rendimiento y estabilidad

- [ ] El contenido principal aparece pronto en móvil.
- [ ] Las imágenes se sirven en dimensiones y formatos adecuados.
- [ ] La primera imagen importante no se carga tarde sin motivo.
- [ ] Elementos tardíos tienen espacio reservado y no desplazan botones.
- [ ] Menús, filtros y formularios responden sin pausas visibles.
- [ ] Fuentes y pesos se limitan a los utilizados.
- [ ] Vídeos, mapas, chats y scripts externos se cargan con criterio.
- [ ] PageSpeed Insights no muestra un bloqueo grave sin investigar.
- [ ] Se han revisado datos de campo si están disponibles.

No persigas una nota aislada. Comprueba LCP, INP y CLS con la guía sobre [por qué una web lenta pierde clientes](/blog/web-lenta-negocio-local), y relaciona cada hallazgo con una tarea visible.

## 9. Seguridad, dominio y recuperación

- [ ] El dominio y las cuentas principales pertenecen al negocio.
- [ ] HTTPS funciona en todas las páginas.
- [ ] HTTP redirige a la versión segura.
- [ ] No hay contenido mixto.
- [ ] Certificado y dominio tienen renovación y alertas.
- [ ] Las cuentas usan contraseñas únicas y autenticación multifactor cuando existe.
- [ ] Se han retirado usuarios que ya no participan.
- [ ] Plugins, dependencias y plataforma están revisados.
- [ ] Existe una copia reciente de archivos, base de datos y configuración.
- [ ] El procedimiento de restauración está documentado y probado.
- [ ] Hay una vuelta atrás para la migración o cambio de DNS.

Aclara quién gestiona [dominio, hosting y SSL](/blog/dominio-hosting-ssl-para-negocios), las copias y las actualizaciones. Publicar sin saber quién puede restaurar la web convierte una incidencia pequeña en una emergencia.

## 10. Textos legales y privacidad

- [ ] El titular del negocio y los datos obligatorios están identificados según el caso.
- [ ] Avisos, privacidad, cookies y condiciones han recibido la revisión aplicable.
- [ ] Los formularios enlazan la información que corresponda antes de enviar.
- [ ] Los proveedores que reciben datos están inventariados.
- [ ] Consentimiento y preferencias funcionan de acuerdo con la configuración aprobada.
- [ ] En ecommerce se explican precio total, entrega, devolución y atención.
- [ ] Los textos coinciden con la operativa real.
- [ ] No se ha copiado una política de otra web.

Esta lista no ofrece asesoramiento jurídico. Las obligaciones dependen del negocio, sector, público, territorio y herramientas. Comprueba las normas aplicables y solicita revisión profesional.

## 11. Plan del día de lanzamiento

Define una ventana, responsables y orden:

1. Crear copia y registrar el estado anterior.
2. Congelar cambios de contenido durante la migración.
3. Publicar archivos, datos y configuración.
4. Activar DNS o redirecciones según el plan.
5. Comprobar HTTPS y páginas principales.
6. Enviar formulario, reserva o compra de prueba.
7. Revisar errores de servidor y navegador.
8. Confirmar analítica y rastreo.
9. Informar al equipo de que el canal está abierto.
10. Mantener una persona disponible para volver atrás si existe un bloqueo.

No anuncies la nueva web antes de completar las pruebas sobre el dominio público.

## 12. Las primeras horas y semanas

- [ ] Vigilar errores 404 y 500.
- [ ] Revisar entregabilidad de formularios y correos.
- [ ] Confirmar pedidos, reservas o contactos con el equipo.
- [ ] Inspeccionar páginas prioritarias en Search Console.
- [ ] Comprobar sitemap y redirecciones.
- [ ] Observar rendimiento real cuando aparezcan datos.
- [ ] Registrar problemas y priorizarlos por impacto.
- [ ] Corregir primero bloqueos, después detalles visuales.

El lanzamiento no termina el proyecto, pero sí debe abrir una versión segura, usable y medible. Si quieres coordinar la revisión técnica y de contenido antes de publicar, puedes [preparar el lanzamiento con IB Studio](/#contacto).
