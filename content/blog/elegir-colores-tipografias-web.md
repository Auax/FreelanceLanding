Elige colores y tipografías por la función que cumplen, no por una imagen de inspiración aislada. Una web necesita fondo, texto, enlaces, acciones, bordes y estados. También necesita títulos, párrafos, etiquetas y cifras que se distingan sin cargar una colección enorme de fuentes.

Un sistema pequeño y consistente suele dar más identidad que cambiar de estilo en cada sección.

## Empieza por el material que ya pertenece a la marca

Reúne logotipo, colores usados en local o producto, tipografías con licencia y ejemplos impresos. Después separa lo obligatorio de lo heredado por costumbre.

Un color puede funcionar en un rótulo y fallar como texto sobre una pantalla. Una tipografía del logotipo puede ser adecuada para una palabra y cansar en párrafos. La web no tiene que copiar cada aplicación; debe traducir la identidad a lectura e interacción.

Si todavía no existe una marca definida, escribe tres atributos concretos. “Cercana, precisa y tranquila” ayuda más que “moderna y única”. Busca decisiones que expresen esos atributos sin sacrificar claridad.

## Da una función a cada color

Construye la paleta por roles:

- Fondo principal.
- Superficie secundaria.
- Texto principal.
- Texto secundario.
- Acción principal.
- Enlace.
- Borde y separador.
- Error, aviso y éxito.
- Foco de teclado.

Un mismo color de marca puede aparecer en botones, enlaces y detalles, pero no todos los elementos deben competir con la misma intensidad. Reserva el mayor contraste visual para las acciones importantes.

Documenta los códigos y combinaciones, no solo una fila de muestras. “Azul 600 sobre blanco para botones” es una regla; `#123456` por sí solo no lo es.

## Comprueba contraste en parejas reales

WCAG 2.2 establece para el nivel AA un contraste mínimo de 4,5:1 para texto normal y 3:1 para texto grande, con excepciones concretas. Los componentes y estados también tienen requisitos que conviene revisar.

Mide:

- Texto sobre cada fondo usado.
- Etiqueta y fondo del botón normal, hover y foco.
- Enlace dentro de párrafos.
- Texto tenue, precios anteriores y ayudas.
- Mensajes de error.
- Campos y sus límites visibles.

No aclares el texto secundario hasta hacerlo casi invisible para crear jerarquía. Puedes reducir tamaño, peso o espacio con cuidado, pero la información sigue necesitando lectura.

El color tampoco debe ser la única señal. Añade texto a los errores y un subrayado o diferencia adicional a los enlaces cuando el contexto lo necesite. La guía de [accesibilidad web para negocios](/blog/accesibilidad-web-pequenos-negocios) incluye más pruebas.

## Elige tipografías según los textos reales

Prueba nombres de servicios, direcciones, precios, acentos, números y párrafos largos. Una muestra con “Aa Bb Cc” no revela cómo se lee el contenido del negocio.

Revisa:

- Legibilidad en tamaños pequeños.
- Diferencia clara entre pesos.
- Cursivas y caracteres del español.
- Números para precios, horarios o tablas.
- Anchura de títulos en móvil.
- Licencia para uso web.
- Formatos y peso de los archivos.

Una familia con varios pesos puede cubrir toda la web. Si combinas dos, asigna una función estable, por ejemplo una para títulos y otra para texto. Tres o cuatro familias suelen crear ruido y más descargas.

## Construye una escala, no una colección de tamaños

Define estilos para:

- Título principal.
- Títulos de sección.
- Subtítulos.
- Párrafo.
- Texto pequeño y etiquetas.
- Botones.

La diferencia debe ser visible sin depender solo del tamaño. Peso, espacio y posición también crean jerarquía. Evita párrafos demasiado anchos; una línea extensa dificulta volver al comienzo de la siguiente.

Usa una altura de línea cómoda y deja espacio entre bloques. En móvil, ajusta los títulos para que una palabra larga no rompa el diseño. Permite ampliar el texto sin ocultar contenido.

## Cuida la carga de fuentes

Cada familia, peso y estilo puede implicar un archivo. Carga solo los que usas. Una fuente variable puede reunir varios ejes en un archivo, pero no siempre pesa menos que dos cortes bien seleccionados. Comprueba el caso real.

Utiliza formatos modernos y configura una estrategia para que el texto aparezca mientras llega la fuente. Escoge una fuente de respaldo con proporciones parecidas para reducir saltos de diseño. Las buenas prácticas de web.dev recomiendan prestar atención a carga, precarga necesaria y cambios de diseño provocados por fuentes.

Una tipografía del sistema puede ser una buena elección para texto si velocidad y familiaridad pesan más que una forma exclusiva. La identidad también se construye con composición, color, fotografía y voz.

## Prueba estados, no solo una portada estática

Una paleta aprobada en una captura puede fallar al usarla. Diseña ejemplos de:

- Botón normal, al pasar, al pulsar, desactivado y con foco.
- Campo vacío, completo, con error y desactivado.
- Enlace visitado cuando sea útil distinguirlo.
- Tarjeta sobre fondo principal y secundario.
- Aviso de éxito y de problema.
- Navegación móvil abierta.

Comprueba también modo de alto contraste cuando sea relevante, impresión si los clientes imprimen documentos y pantallas con brillo bajo.

## Evita convertir una tendencia en identidad

Una tipografía extrema o una combinación de moda puede fechar la web pronto y dificultar cambios. Usa las tendencias como recursos, no como instrucciones. El artículo sobre [tendencias de diseño web en 2026](/blog/tendencias-diseno-web-2026) separa efectos útiles de novedades que necesitan una razón.

Si partes de una [plantilla o un diseño a medida](/blog/plantilla-vs-diseno-web-a-medida), documenta el sistema de la misma forma. Una plantilla no impide tener identidad; requiere adaptar sus variables con coherencia.

## Checklist de un sistema listo para desarrollar

- [ ] Cada color tiene una función.
- [ ] Las combinaciones de texto y fondo pasan contraste.
- [ ] Error y éxito no dependen solo del color.
- [ ] Hay una o dos familias con licencia web.
- [ ] Solo se cargan pesos utilizados.
- [ ] La escala tipográfica funciona en móvil.
- [ ] Los párrafos mantienen una anchura cómoda.
- [ ] Estados de botones, enlaces y campos están diseñados.
- [ ] El foco de teclado es visible.
- [ ] Zoom y texto grande no ocultan acciones.
